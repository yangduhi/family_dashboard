# 키즈노트 당일 준비물

가족용 보드는 인증된 가족에게 오늘의 준비물과 다가오는 일정을 표시한다. 설정 아래의 키즈노트 아이콘을 누르면 상세창이 열린다. 준비물이나 안내가 있으면 아이콘을 강조한다. 0건이어도 완료 여부와 확인 시각을 조회할 수 있다. 수집기가 만든 검증 현황은 가족 공지 목록과 아이콘 강조에서 제외한다. 운영 판정과 검증 기록은 유지한다. 공개 Pages에서는 가족 조회를 시작하지 않는다.

상세창 상단에는 적용일과 오늘 준비물 판정을 표시한다. 본문은 준비물, 일정, 특이사항으로 구성한다. 준비물에서는 오늘 챙길 품목과 이후 준비 안내를 나눈다. 일정과 이후 준비는 확인된 적용일 순으로 표시하며, 날짜를 확인하지 못한 항목은 뒤에 둔다. 품목 수량, 조건, 출처와 안내의 확인 필요 상태는 별도 줄이나 표지로 읽을 수 있다. 데이터가 없는 분류는 생략한다. 태블릿 가로 화면에서는 분류를 나란히 배치하고 좁은 화면에서는 세로로 배치한다.

주간 준비물은 서울 적용일 기준 월요일부터 금요일까지 다섯 날짜를 표시한다. 월~금에는 이번 등원 주를, 토요일 00:00부터는 다음 등원 주를 표시한다. 주간판에는 날짜별 칸만 두며, 주말에도 당일 판정의 기준 날짜는 그대로 사용한다. 각 칸은 당일 품목과 해당 날짜의 준비 안내를 수량·조건·확인 상태와 함께 보여준다. 수신된 안내가 없는 날짜는 “등록된 안내 없음”으로 표시한다. “준비물 없음”은 해당 날짜의 당일 판정이나 명시적인 보호자 확인을 따른다. 행사일과 게시일로 준비물 제출일을 추정하지 않는다. 주말·주간 범위 밖·날짜 미확인 안내는 아래 상세 목록에서 계속 확인할 수 있다.

가족 API의 `weekPreparations`는 이번 주와 다음 주 평일의 준비 안내를 제공한다. 이미 지난 평일의 공지도 주간 조회에 포함한다. 날짜 칸에는 검증된 안내를 배치하고, 날짜가 있어도 확인이 필요한 안내는 주간판 아래 **확인할 준비 안내**로 분리한다. 이전 API에 접속하면 당일 응답의 공지로 주간판을 구성한다. 이 경우 지난 날짜에는 당시에 게시된 준비물이 빠질 수 있다. 주간판은 과거 일일 판정의 이력 화면이 아니다.

## 수집과 원본 확인

가족 보드에서 **키즈노트**를 누르면 상세창 안에 **월간 일정표** 아이콘이 나타난다. 아이콘을 누르면 서울 기준 이번 달 달력이 열린다. 일정표를 닫으면 같은 상세창의 일정표 아이콘으로 포커스가 돌아간다. 태블릿 달력의 날짜 칸은 같은 높이로 정렬한다. 긴 행사명과 같은 날의 여러 행사도 끝까지 읽을 수 있어야 한다. 날짜와 행사명, 확인된 시작 시각을 표시한다. 표의 대상 칸에서 확인된 1세반 전용 행과 여러 연령 중 1세가 포함된 행은 각각 다른 문구로 강조한다. 전체 공통, 다른 연령, 대상 미확인은 구분한다. 반 이름을 연령과 연결할 때는 해당 기간에 유효한 반 정보가 필요하다. 다른 공지에서 대상을 보완할 때는 같은 행사라는 근거와 해당 공지의 최신 개정을 확인한다. 참여 사실만 확인되면 그 범위만 표시한다. 행사의 준비물과 제출 기한은 따로 검증한다. 행사에 사용할 준비물은 제출일이 없어도 행사와 함께 표시하며, 행사일만으로 당일 지참을 확정하지 않는다.

달력은 인증된 가족의 당일 API에서 이번 달(`monthlyCalendar`)과 다음 달(`nextMonthlyCalendar`)을 받는다. 이번 달 공지에 미리 실린 다음 달 행사는 실제 행사일이 속한 달에서 조회한다. `AVAILABLE`은 확인된 월간표, `NEEDS_REVIEW`는 일부 행이나 개정이 검토 중인 월간표, `PENDING`은 해당 달 자료 대기다. 일부 행이 검토 중이면 확인된 일정을 표시하고, 달력 전체에 일괄 확인 문구를 붙이지 않는다. 토요일과 일요일의 날짜 칸은 옅은 회색으로 구분한다. 보호자가 특정 준비물의 지참일을 확인하면 그 품목의 주간·월간 안내에 확인된 날짜를 사용한다. 같은 공지의 다른 품목은 각자의 근거를 따른다. 달의 경계는 서버 적용일을 따른다. 공개 보드는 가족 아이콘을 표시하거나 가족 API를 조회하지 않는다.

비공개 GitHub Actions가 승인된 자녀·기관·반에서 이미 읽은 기관 발신 문서를 수집한다. 새 공지의 시작일은 2026년 11월 1일 KST다. 알림장은 작성일 기준 최근 7일과 당일을 조회하며, 등록된 활성 출처는 변경·정정·취소 여부를 다시 확인한다. 조회 범위의 공식 끝과 전날 알림장 유무를 검증한다. 상대 날짜는 원문의 게시일로 해석한다.

공식 본문 전체와 첨부의 원본 바이트를 확인한다. 이미지의 모든 프레임은 원해상도에서 분석한다. 월간표는 날짜 열, 대상 연령·반, 행사와 지참 지시를 연결하고 표 밖 안내와 별도로 대조한다. HWPX는 실제 본문 구역을 확인한다. 첨부 누락, 미열람 또는 불분명한 적용 조건은 사유를 기록한다. 개정 이력과 원본 해시가 같을 때만 해당 검수 범위의 판독을 재사용한다.

목록·상세·첨부의 요청 예산은 수집당 200회다. 수집 시간은 300초, HTTP 요청은 20초다. 비공개 DB 작업은 별도의 첨부 처리 시간 480초 동안 같은 요청 예산을 사용한다. 이어받기는 저장된 경계를 다시 대조한다. 순환 페이지나 미완료 조회는 전체 자료 확인으로 집계하지 않는다.

## 판정과 게시

비공개 저장소의 SQLite는 검토 근거와 수집 진행 상태를 보관한다. 가족 보드의 D1은 승인 범위, 게시 결과, 예정 품목과 마감 이력을 관리한다. Hive에는 승인된 비식별 지시만 보낸다. 원문과 인증 정보는 운영 로그·공개 보드에 저장하지 않는다.

| 게시 상태 | 화면에서 확인할 내용 |
|---|---|
| `READY` | 적용일·대상·출처가 검증된 품목, 수량과 조건 |
| `EMPTY` | 필요한 출처를 모두 검증한 뒤 확정한 준비물 0건 |
| `NEEDS_REVIEW` | 전체 판정에 부족한 근거와 이미 확인한 안내 |
| `AUTH_REQUIRED` / `PENDING` | 수집 계정 재인증 또는 갱신 대기 |

보호자 확인은 자동 판정과 구분하여 표시한다. 같은 행사·대상의 반복 지시는 중복을 제거한다. 정정이나 취소는 원래 지시와 적용일이 연결된 경우에 반영한다. 부분 검수나 특정 날짜에 한정한 결과를 다른 날짜 전체로 확대하지 않는다.

05:10 KST 최초 수집 후 05:40에 정정을 다시 확인한다. 06:05에 06:00 시점의 마감을 기록하고, 06:17에 재수집 실행 ID와 완료 게시 세대·게시 시각·`ON_TIME` 기록을 대조한다. 마감 후 복구 게시도 원래의 마감 실패 이력을 보존한다.
